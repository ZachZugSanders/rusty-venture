# Rusty Venture — Tiered Maturity Scanning

## Overview
Evolve the maturity system from 25 binary pass/fail signals into a three-tier progressive
scanning system. Each tier unlocks only after the previous tier is 100% complete. Higher
tiers move from static file checks → content quality → active functional validation.

---

## Tier Definitions

### Tier 1 — Static Discovery (current, always runs)
All 25 existing signals. No execution, no network. Fast, safe, zero side effects.
Entry point for every repo scan.

### Tier 2 — Content Quality (unlocks when Tier 1 = 100%)
Passive content inspection — read and analyze file *contents*, not just existence:
- README has real substance (sections, installation instructions, >N words)
- CI config references an actual test command
- CHANGELOG has versioned entries (semver format)
- License is a recognized SPDX identifier
- Dockerfile doesn't run as root (content parse)
- Dependency audit passes (cargo audit / npm audit inside container)
- Test files contain real test functions
- Lock file is not stale relative to manifest

### Tier 3 — Active Functional Validation (unlocks when Tier 2 = 100%)
Actually *run* things inside the isolated analysis container:
- `tests_pass` — run test suite, must exit 0
- `build_succeeds` — compile/build the project
- `docker_build_succeeds` — attempt `docker build` if Dockerfile present
- `docker_compose_valid` — `docker compose config` validates
- `linter_passes` — run configured linter (clippy, eslint, ruff, etc.)

---

## Unlocking Rules
- A scan always runs **exactly one tier** (the current max_unlocked_tier for the repo)
- All signals in a tier must pass to unlock the next tier
- Partial tier completion does NOT advance the tier
- First scan of any repo always runs Tier 1
- User triggers subsequent tier scans manually from the UI (or auto on next scheduled scan)

## DB Schema (final state after all phases)

```sql
-- 004_commit_hash
ALTER TABLE scans ADD COLUMN commit_hash TEXT;
CREATE INDEX IF NOT EXISTS idx_scans_repo_commit ON scans(repo_id, commit_hash);

-- 005_tiers
ALTER TABLE repos        ADD COLUMN max_unlocked_tier INTEGER NOT NULL DEFAULT 1;
ALTER TABLE scans        ADD COLUMN scan_tier         INTEGER NOT NULL DEFAULT 1;
ALTER TABLE scan_signals ADD COLUMN tier              INTEGER NOT NULL DEFAULT 1;
CREATE INDEX IF NOT EXISTS idx_repos_tier ON repos(max_unlocked_tier);
```
